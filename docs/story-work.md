## 범위와 결과물

- 범위: PRD 핵심 사용자 흐름과 MVP 화면(Home / Write / Review / My English)의 프로토타입 제작 ~ 검수
- 결과물: 인터랙티브 프로토타입 + 검수 결과
- 규칙 SSOT: docs/design.md (1 Overview → 2 Colors → 3 Typography → 4 Layout & Shapes → 5 Components → … → 9 Do's and Don'ts → 11 Source for Gate Extraction)
- 입력 기준: docs/prd.md

## AS-IS 문장 (7)

- S1. 나는 UIbowl에서 경쟁사 레퍼런스를 수집한다.
- S2. 나는 수집한 레퍼런스를 분석하고 우리 서비스에 반영할 요소를 정리한다.
- S3. 나는 분석 내용을 바탕으로 우리 서비스의 화면 설계 문서를 구체화한다.
- S4. 나는 Figma에서 레퍼런스와 화면 설계서를 반영해 390×844 사이즈의 UI 키스크린 2~3개를 제작한다. ⏸
- S5. 나는 제작한 키스크린을 내부 관계자들과 협의하고 컨셉 시안을 확정한다. → 내부 관계자
- S6. 나는 컨펌된 시안을 바탕으로 디자인 토큰과 컴포넌트를 제작하고 전체 화면 디자인을 진행한다. ⏸
- S7. 나는 완성된 화면의 토큰과 컴포넌트가 우리 디자인 가이드를 위반하지 않았는지 검토한다. ⏸

## 게이트 초안 (R5에서 확정)

| 게이트 | 멈칫 이유 | 종류 | 셀 수 있는 조건 |
|---|---|---|---|
| G1 | 레퍼런스 양·무드 판단 | 기계 1차 + 사람 확인 | 레퍼런스 ≥ 10개, 각 무드 태그 1개 필수, `손글씨/편안함` 태그 ≥ 30%. 무드 적합성은 사람이 확인. (레퍼런스 기준이며 UI 손글씨 폰트 규칙 아님) |
| G2 | 무엇을 토큰으로 만들지 어려움 | 기계 | 대상 5종(색·간격·모서리·타이포 크기/굵기·그림자) 하드코딩 값 0개. 동일 값 2회 이상 사용 시 토큰 후보로 표시. |
| G3 | 눈으로 하나씩 대조 | 기계 (읽기전용 판정 스크립트) | design.md 허용값 밖의 값 0개. 위반은 `화면/요소/값/기대값` 목록으로 출력. |

기타 셀 수 있는 규칙 후보: 프레임 390×844, 키스크린 2~3개.
